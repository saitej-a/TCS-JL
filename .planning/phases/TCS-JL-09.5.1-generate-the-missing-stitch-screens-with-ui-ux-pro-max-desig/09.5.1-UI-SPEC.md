## Spacing Scale

Declared values (multiples of 4; identical to 9.2–9.5 usage — do not invent new steps):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | icon/glyph gaps, badge padding |
| sm | 8px | compact element spacing |
| md | 16px | default element spacing, card padding (mobile) |
| lg | 24px | section padding, legal prose block gaps |
| xl | 32px | layout gaps between major sections |
| 2xl | 48px | major section breaks |
| 3xl | 64px | page-level spacing |

Exceptions: none. The legal prose measure is the one new structural constant: **65–75 characters**, implemented as `max-w-[72ch]` (or the `max-w-prose` equivalent the codebase standardizes on) on prose containers only — never on the shell or the TOC rail. Every interactive element keeps the shipped `min-h-[44px]` target.

## Copywriting Contract

**Voice:** plain, factual, peer-community. Every claim must be backed by shipped code; where the product cannot do something yet, say so explicitly in the "Not tracked yet / Not available yet" register established by 9.5 T6 (screen #1 carries the model).

**Banned copy (the §3.3 do-not-copy ledger — never appears in product copy):** passwordless authentication, SHA-256 HMAC email hashing, "cryptographically signed" reset tokens, "Fields locked during cryptographic hashing", IndexedDB timeline drafts, "dispatch velocity percentiles", any data-protection-officer inbox or SLA ("hello@tjt-community.example", "7 business days"), WebAuthn/TOTP "rollout" promises, "three visibility modes", "TJT-Auth v2.4" / "TJT-Core v2.4" / "ERR_TOKEN_EXPIRED" style version or error-code strings, and any numeric token-lifetime claim (D-12).

**Required facts (rendered verbatim in spirit, numbers only where real):**
- Masked address form: `a***@example.com` (the server's masking shape).
- Deletion: immediate, self-service via Settings → Danger Zone, irreversible — no grace period (D-02).
- Trackers: "no analytics SDKs, ad pixels or behavioural trackers" + the FCM/browser-push transport clause (D-04).
- Password rules: minimum 10 characters + uppercase + lowercase + digit + special — sourced from the single `passwordRules.ts` module, never restated inline (D-09/D-10).
- Reset link: "time-limited and single-use" — the real window is 60 minutes (`PASSWORD_RESET_TIMEOUT = 3600`) and may be stated, since it is a server setting verified at write time; verification links stay qualitative (D-12's asymmetry note).
- Verification: "single-use and time-limited", no number (D-12).

**Authorship:** the three legal pages' words are the user's (D-15); the executor renders skeletons and pastes the user's copy into content modules before completion — no placeholder prose ships (D-16).

## Per-Surface Contracts

### §5.4 Visitor shell (new — `VisitorShell`)

- Header: logo link home + nav `Community` (`/community`) + `About` (`/about`) + auth zone. Auth-aware (D-07): visitor sees `Sign in` → `/login` and `Create account` → `/register` (shipped labels, pinned by `LandingPage.test.tsx:64–65`); a session swaps them for the account affordances (profile/settings entry) — never `[Register]` for a signed-in reader.
- Footer: link row `About • Privacy Policy • Terms of Service • Explore Community` (→ `/about`, `/privacy`, `/terms`, `/community`) above `<Disclaimer variant="footer" />`. Row order and labels per §5.4; `min-h-[44px]` targets on every link.
- `LandingPage` composes the same header/footer components in its own page shell (D-06/D-08) — landing visibly gains the two nav links and the footer row; the landing test pins are the regression fence.
- Rejected frames (recorded): riding PublicShell/AppShell (app sidebar/search on a policy page) and staying chromeless (strands the reader). Screen #5's app-sidebar frame is the one part of its layout that is NOT adopted.

### §7.13 Legal pages (`/about`, `/privacy`, `/terms` — new)

- One shared `LegalLayout`: page title, section TOC (anchor links per `##` section; sticky on ≥lg, collapsed `<details>` on mobile — executor's discretion per CONTEXT), prose measure, one honesty line (D-03) rendered as a caption-voice sentence directly under the title, and the three content modules as data.
- **No `Last updated` line** (D-14). **No TOC tabs-over-siblings** — the three URLs stay distinct routes (§3.1).
- `/privacy` sections must cover: what we collect (self-reported milestones + cohort metadata), email handling (masking + what the address is used for), trackers (D-04's scoped claim), notifications & device tokens (per-device scoping), your controls (identity-mode field as shipped — ONE visibility field, not three), deletion (D-02's immediate/anonymisation facts), and the community-data disclaimer (aggregates are `COMMUNITY_REPORTED`, threshold-suppressed `<5`).
- `/about` covers mission (PROJECT.md's core value), the non-affiliation boundary (§1's Important Product Boundary), and explicitly does NOT document contribution guidelines (no LICENSE/CONTRIBUTING exists — deferred idea).
- `/terms` covers acceptable use mirroring the moderation vocabulary (SPAM, HARASSMENT, MISINFORMATION, ABUSIVE_CONTENT, SCAM, OTHER), enforcement (report flow → review actions), and the non-affiliation restatement.

### Reconciled auth/security pages (screens #1–#4)

- `ResetPasswordPage` (`/reset-password/:token`): the reveal toggles already ship inside the shared `Input` (F1 of RESEARCH) — reconciliation *verifies* them (backstop). Real work: client validation switches to the shared `passwordRules.ts` (per-rule check, not just length); hints state the real rules; the failed-submit feedback keeps the `loading` → error-strip triple; the token pill (error path showing the attempted token) uses `overflow-wrap: anywhere` + `min-inline-size: 0`, never `word-break: break-all`; copy says "time-limited and single-use" + the 60-minute window per the Copywriting Contract.
- `RegisterPage`: same rules module drives its gate, hint ("Must be at least 10 characters…"), and per-rule error messages; navigates to `/verify-email-pending` with `{ state: { email } }`.
- `VerifyEmailPendingPage`: the `window.prompt()` becomes a labeled in-card email `Input` (prefilled from router state); resend button keeps cooldown + `loading`; success/rate-limit banners stay `SuccessStrip`/`ErrorStrip`; masked address rendered `font-mono-code`.
- `VerifyEmailActionPage`: success state per cleaned screen #3 (single production state, no states strip); invalid/expired path keeps the wrapping-truncated token display with `overflow-wrap: anywhere`.
- `SettingsSecurityPage` (screen #1): copy already matches the real decision set (masked address, "Active sessions — Not tracked yet", "2FA — Not available yet"); reconciliation = confirm and only fix drift found against the screen; no new promises.
- Every state on these pages renders from React state — never as stacked annotation blocks (the §3.3 lesson).
- **v2 correction:** the toggles on the two password forms are existing `Input` behavior (pinned by `Input.test.tsx:26`), not new work; the UI Considerations row "toggles inside AuthField layout" is therefore a verify-only backstop.
