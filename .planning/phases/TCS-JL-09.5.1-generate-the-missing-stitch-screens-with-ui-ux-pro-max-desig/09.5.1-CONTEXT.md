## 2. ui-ux-pro-max intelligence that shaped the prompts

Per the skill's query contract (one dominant intent per query, retry once when the hit is empty),
these focused searches ran against `ux`:

| Query | Finding used | Severity |
|---|---|---|
| `email verification token` | **Long Token Wrapping** — URLs/identifiers must not force horizontal overflow; `overflow-wrap: anywhere`, `min-inline-size: 0`; never `word-break: break-all` on prose | High |
| `password reset form validation` | **Password Visibility** (show/hide toggle) · **Submit Feedback** (loading → success/error) · **Form Labels** (associated labels, never placeholder-only) · Stacking Context | Med / High / High / Med |
| `reading measure line length policy page` | **Line Length** 65–75 characters (`max-w-prose`) · **Line Height** 1.5–1.75 (`leading-relaxed`) | Med |
| `settings password change security` | Password Visibility + Submit Feedback again | Med / High |

These are now baked into the generated screens: the token pill wraps instead of overflowing, every
password field carries an eye toggle, every submit has a loading → success/error triple, legal prose
is constrained to a readable measure, and no field is placeholder-only.

### 3.1 Prompt hygiene — the 9.5 §5.2 lesson applied

9.5's screens came back carrying **annotation artifacts** ("DESIGN NOTE" captions, dark-value mapping
strips, extra sample rows) because the prompts asked for dark-theme annotations. This phase's prompts
carried an explicit prohibition instead — *"REAL CONTENT ONLY — do not print any 'DESIGN NOTE'
caption, dark-value mapping table, extra sample strip, or annotation text anywhere in the artwork"* —
and asked for line-art SVG icons only (no emoji). The generator's own summaries report no
annotations, which is the expected result of the instruction, **not yet a pixel-verified claim** (§5).

### 3.2 Real-contract constraints encoded in the prompts (no mock fiction)

- **Security**: three labeled password fields with show/hide toggles, a `Change password` state
  triple, a reset-link row with the **masked** address (`a***@example.com`), and an honest
  "Active sessions — not tracked yet / 2FA — not available yet" info card matching 9.5 T6's decision
  that no sessions list exists server-side.
- **Verification pending**: masked address, resend button **with its cooldown state**
  (`Resend available in 42s`), success + rate-limit banners, a 3-step flow strip, and no
  auto-redirect.
- **Verification action**: two variants — verified (with the server-stamped timestamp) and
  invalid/expired, where the attempted token renders as a **wrapping** truncated identifier.
- **Reset password**: strength meter + requirement checklist (text-labelled, never colour alone),
  `Password updated. Taking you to sign in…` success state, mismatch error, and an expired-token
  variant that states the old password is unchanged until a new one is saved.
- **Legal**: the non-affiliation statement as a brand-50 callout, `Last updated …` in Fira Code, an
  in-page TOC rail, and 65–75-character prose measure.

## 4. What this phase still owes (the implementation half)

The four auth/security routes are **already implemented** (9.2/9.5) and now have references to be
reconciled against — the same "match the reference minus annotations" check 9.5 used. The real
remaining build work is the **informational/legal pages**, which are still `StubPage` placeholders in
`frontend/src/pages/index.tsx` while the visitor header and footer already link to them.

Suggested plan shape for `/gsd-plan-phase 09.5.1`:

1. **Legal/informational pages** — implement `/about`, `/privacy`, `/terms` as real pages in the
   visitor shell (single shared layout + content module, matching screen #5's TOC + measure rules).
2. **Reference reconciliation** — read screens #1–#4 against the shipped `SettingsSecurityPage`,
   `VerifyEmailPendingPage`, `VerifyEmailActionPage`, `ResetPasswordPage`; fix drift (token wrapping,
   password visibility toggles, submit-feedback triples, label association) and record any
   deliberate divergence.
3. **Gates + record** — lint / typecheck / `tsc -b` / vitest / build, then a VERIFICATION entry with
   the reconciliation ledger.
