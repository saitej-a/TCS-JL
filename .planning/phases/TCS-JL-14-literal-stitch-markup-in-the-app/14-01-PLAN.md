# Plan 14-01 — Literal Stitch Markup

**Goal (backward):** after this plan, the app's screens **are** the Stitch compositions — the same
classes, the same element tree, the same glyphs, the same two skins — rendered by the working
React app, with every piece of content the API cannot supply carrying an enumerated awaiting
state instead of fiction. `RECONCILIATION-14.md` maps all 45 compositions to their ported sources
and lists, per screen, the awaiting slots and every deviation from literal.

## Global conventions (binding on every task)

- **G-1 (D-01):** the composition's classes and hierarchy are copied **verbatim** into the
  component. No repainting, no token substitution, no "improving" spacing. Phase 12's G-1/G-2 and
  its v1 sweep are **superseded** on ported surfaces (D-06); the supersession text is written in
  the closing task, not before, so the gate keeps working for unported files until the last one
  lands.
- **G-2:** the app's plumbing is untouched — auth, `client.ts`, guards, PWA, push, routing. This
  phase moves markup, behaviour-as-React, and presentation assets; it does not change contracts.
- **G-3:** no fabricated value ships. A composition value the API has no source for renders an
  em dash with `data-awaiting="<field>"` inside the mock's exact frame, and is listed in the
  screen's row. The fiction strings themselves (every one is enumerated in `09.5
  VERIFICATION.md §3` / `09.5.1-CONTEXT.md §3.3`) must not appear in the ported source.
- **G-4 (D-03):** each screen root carries its family's scope class (`skin-v1` / `skin-v2`), and
  the screen uses only its own family's vocabulary. A v1 screen never renders a `brand-*` class;
  a v2 screen never renders `indigo-*`.
- **G-5 (D-05):** inline `<script>`, `onclick` and `onsubmit` never enter JSX. The composition's
  behaviour becomes React state/handlers, pinned by the screen's suite. Modal bodies render
  inside `Modal.tsx`; nothing re-implements dialog mechanics.
- **G-6 (D-08):** every ported screen passes `node scripts/stitch-fidelity.mjs` for its
  composition before its task commits — classes present, glyphs named, section order preserved,
  fabricated strings absent, awaiting slots declared.
- **G-7:** assets are vendored, never fetched at runtime. No `cdn.tailwindcss.com` and no
  `fonts.googleapis.com` reference may exist in `frontend/index.html` or any rebuilt source.
- **G-8 (9.5.1 D-04):** the legal pages keep their awaiting-copy contract verbatim; the
  compositions' legal fiction (version chips, "Last updated", hashing/DPO claims) stays out.

## must_haves

truths:
  - Every one of the 45 `code.html` compositions has a `RECONCILIATION-14.md` row naming the
    ported source(s) — and `node scripts/stitch-fidelity.mjs --all` passes for all 45, proving the
    composition's class tokens, glyph names and section order are present in that source.
  - Both font families and Material Symbols render from `frontend/public/fonts/`; zero
    `cdn.tailwindcss.com` and zero `fonts.googleapis.com` references exist in `index.html` or in
    any rebuilt source (G-7).
  - Every value the API cannot supply carries `data-awaiting="<field>"`, is enumerated in its
    screen's row, and no fabricated value string from the 9.5/9.5.1 ledgers appears anywhere in
    `frontend/src` (G-3).
  - The two skin families are scoped per screen: a v1 screen declares `.skin-v1` and renders no
    `brand-*`; a v2 screen declares `.skin-v2` and renders no `indigo-*` (G-4).
  - Behaviour parity: every interactive affordance in the 21 behaviour-bearing compositions
    (tabs, radio cards, accordions, dropdowns, copy buttons, modal openers) exists as React
    behaviour and is pinned by a suite (G-5).
  - The app still works: lint 0 errors, typecheck and `tsc -b` clean, the full vitest run green,
    build green, and the PWA still precaches and registers (G-2).
  - The contrast audit is re-derived against the literal palettes, with each failing pair either
    fixed (recorded as a deviation from literal) or accepted and listed (D-06).
  - Phase 12's v1 sweep and token-repaint rule are superseded **in writing** in the four places
    D-01 names, so no later phase inherits a gate that this one invalidated.
  - `lucide-react` is removed from the dependency tree once the last screen is ported (D-04).
