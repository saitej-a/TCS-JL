The system is full-stack: Django models, REST endpoints, Django Channels WebSocket consumers with single-use ticket authentication, and a responsive frontend view using the v2 design system and ui-ux-pro-max guidelines.

<threat_model>
<asset name="Realtime Message Stream" value="Publicly accessible to authenticated candidates">
  <threat id="T-1" severity="high" description="Unauthorized access to chat streams or spoofed identity.">Mitigation: Single-use opaque tickets with 60-second TTL stored in Redis cache. Handshake deletes the ticket immediately upon validation. Anonymous candidate profiles mask display names via standard AuthorPublicSerializer.</threat>
  <threat id="T-2" severity="medium" description="Message flood, spam, or denial of service on WebSocket.">Mitigation: 10-second duplicate message debounce in Redis; body validation enforcing non-blank and max 2000 characters; DRF scoped rate throttling on REST write endpoints.</threat>
  <threat id="T-3" severity="medium" description="Cross-room message tampering or unauthorized deletions.">Mitigation: Messages enforce room matching; deletions restricted to author or staff; tombstone preserved in database (is_deleted=True).</threat>
</threat_model>
